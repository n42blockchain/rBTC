# Original block preparation admission

Budget-bound batch workers now reserve original preparation memory before `BlockPrepareView` allocates its maps or BIP30 lookup begins. Checked estimates cover the prepared transaction arrays, original input/output coin payloads, query-result overlap, hash tables and sets, vector relocation, BIP30 pre-images and net/undo conversion. Canonical input-script size is bounded by the existing execution read contract; this is not a promise that arbitrary third-party backends obey that contract. Deferred script copies retain their separate reservation.

One shared lease follows both `PreparedActiveBlock` and `PreparedDelta`. Conversion carries it into `UtxoChanges` and the streamed `LeasedConnectTransition`. Retained undo attaches the same owner to its immutable payload, including escaped caller handles. If undo is disabled, original preparation storage is dropped before its owner. On the ordinary spool path, original admission stays live through encoding and write completion; decoding later obtains its existing separate allowance. Compatibility collectors/write-back retain transition ownership through commit or discard.

The pressure regression uses a real budget-bound redb store and valid header/block. With one byte less headroom than required, preparation returns a local execution-memory error without moving the tip or retaining extra usage. Releasing pressure admits the same work. Returned undo clones survive both original result and delta destruction while retaining the allowance. The no-undo path retains the created-coin owner across delta/net/streamed-transition conversion and refunds after the final transition drops.

Reservations conservatively cover a whole block and remain pinned until its final owner disappears; they are not shrunk to the final undo size. A refused batch is still fail-closed rather than resumably scheduled. Caller-owned raw blocks, pre-admission header/MTP reads, outer batch metadata, native verifier scratch/stacks, engine mappings, total startup RSS, physical disk quotas and sustained whole-node/full-scale acceptance remain separate open work. No acceptance threshold changed.
