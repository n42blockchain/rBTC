# Streamed archive writes and publication verification

`write_archive` previously built a complete compressed vector and then a second complete container vector before writing. It now compresses into an anonymous temporary file beside the destination, hashes compressed pieces using one fixed 4 MiB buffer, writes the bounded manifest, and copies the payload to the destination. Record validation, compression level/worker selection, record digest and piece format are shared with the existing in-memory encoder. The destination is opened only after compression, digest construction and final container-size checks succeed. Ledger callers retain their existing staging/slot fsync and rename protocol.

For node-bound paths, the temporary file reserves the maximum permitted container size from the existing shared logical 16 GiB spool allowance before file creation or compression. The writer refuses a compressed write beyond that byte bound, and anonymous scratch is removed on success/error/drop before its allowance returns. The reservation is conservative (maximum container size, including for small archives). Destination/staged/retained files are separate owners; this is not a physical disk quota or claim that all archive allocations are admitted. The observed status field remains `execution_spool_reservations`, now also including archive compression scratch.

`verify_archive`, used before staged publication, now verifies manifest and compressed piece hashes through the same file handle with a fixed piece buffer instead of reading the entire compressed container into a vector. Its existing contract remains compressed-container verification; full record verification is performed by the record-reading/validation paths.

A multi-piece, approximately 6 MiB incompressible regression compares the streamed file byte-for-byte with the in-memory encoder, checks the manifest verifier, exhausts the shared temporary allowance and proves denial precedes destination truncation, then retries and verifies complete refund and no leftover scratch files. A writer-bound check proves excess bytes are rejected before reaching the file. Existing staged durability/crash-recovery tests remain part of full regression.

Partial-prefix publication still reads all source blocks before passing a prefix to the now-streamed writer; already-published-prefix comparison also materializes source records. Native compression buffers/workers, shared archive read memory admission, physical disk inventory, typed resource-pressure recovery and finite node batch downshift/retry remain open. This change does not close the total startup/RSS or long-running gates.
