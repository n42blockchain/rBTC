## 已修复问题

| 编号 | 严重度 | 问题与影响 | 修复与回归证据 |
| --- | --- | --- | --- |
| R01 | 高 | redb rebase 提交新身份并清空 overlay 后，压缩失败会触发清理 guard，删除已被数据库引用的新快照/索引；内存仍指向旧 base。 | 提交前停止清理新文件，以保留提交结果不确定时的恢复材料；提交成功后先更新内存，再压缩。新增持久 savepoint 强制压缩失败、检查 UTXO 并重新打开的测试。 |
| R02 | 高 | MDBX 完成目录切换后，重新打开环境失败仍会删除新快照/索引，破坏重启恢复所需的数据。 | 在成功切换后立即解除文件清理，再进行可能失败的 reopen。新增可注入 reopen 失败的私有入口及重新打开恢复测试。 |
| R03 | 高 | 两种 rebase 都用 `File::create` 打开固定 `.tmp` 文件，并预先将它加入清理列表。已有文件会被截断，符号链接会将写入重定向到其他文件。 | 改为 `create_new`，只有成功创建的文件才归本次清理。两种后端均新增保留已有 staging 文件的测试。 |
| R04 | 中 | SAM 每条回复临时创建默认缓冲 reader；状态行与 P2P 首包一起到达时，预读的 P2P 数据随 reader 被丢弃。EOF 前没有换行的回复也会被当成成功。 | 回复读取不越过换行，拒绝未终止行。内存双工流确定性复现旧版本丢失全部尾随数据，修复后测试通过。 |
| R05 | 中 | I2P 公布地址对整个 SAM 私钥文件做 SHA-256，包含了不属于公开 Destination 的私钥尾部，产生不可达的地址。 | 按 certificate 长度截取公开部分后哈希；校验 Base64、长度和残余位，输入密钥在发送命令前检查。固定哈希样本与截断 certificate 测试通过。 |
| R06 | 中 | Tor 创建新服务先发送带 `DiscardPK` 的创建命令，随后无条件再创建一次；第一个服务没有被跟踪或显式撤销。 | 只发送一次创建命令，保留生成/复用的密钥，拒绝缺失密钥的异常结果。原发布/撤销测试增加精确命令数量与内容检查。 |
| R07 | 中 | Tor 回复的固定字节位置及十六进制字段直接切片 UTF-8 字符串；畸形本地回复可触发 panic。回复状态与分隔符也缺少严格校验。 | 切片前验证 ASCII 状态头和分隔符；拒绝非 ASCII hex、未终止行和未支持的数据块。两个 panic 已在旧逻辑上复现，修复后通过。 |
| R08 | 高 | 匿名网络密钥读取错误被 `.ok()` 吞掉，权限错误/符号链接等会被当作不存在，导致静默换身份。密钥写入直接 truncate 目标，可破坏链接指向的文件，写入中断也会损坏原密钥。 | 仅 NotFound 允许生成新身份；用 create-new 的临时文件（Unix 权限 0600）完整写入并同步，再原子替换和同步目录。符号链接、硬链接、权限错误及正常轮换测试通过。 |

R05 的格式依据：SAM 的 SESSION STATUS 返回公开 Destination 与私钥拼接的文件；
公开 Destination 的 certificate 指定其变长边界。
参见 [SAM v3](https://i2p.net/en/docs/api/samv3/)
和 [I2P common structures](https://i2p.net/en/docs/specs/common-structures/)。
原 SAM mock 只有一段短 Base64 字符串，不能表示真实 Destination；
已替换成具有 Ed25519 certificate 和私钥尾部的结构样本。
原 `-~` 样本含非零填充位，改用同样解码为 `0xfb` 的规范编码 `-w`。

R06 的协议依据：`DiscardPK` 可以用于新生成服务，只控制是否返回私钥，
并不意味着第一次创建会失败。
参见 [Tor ADD_ONION](https://spec.torproject.org/control-spec/commands.html#add_onion)。
