# 同步合并、复审与依赖更新（2026-09-05）

## 范围与基线

在本地审计提交 `0601bb3` 上合并远端 `main` 的 `b5c1d00801fcb98ab8d17a6a7f717a3188d8d099`，
纳入新增的 168 个可达提交。远端 2026-06-05 至 2026-09-05 窗口内共有 578 个可达提交，
包含合并提交。重新获取远端后确认此基线未变化。

重点复核新增批量执行、异步写回、回放预取及匿名网络代码与前次修复的交互；
保留前次快照恢复、临时文件、密钥持久化与 ZMQ 生命周期修复。
SAM 合并采用远端逐字节读取和公开 Destination 长度解析，叠加严格输入校验，
并保留远端每实例会话 ID 与入站连接支持。Tor 保留单次服务创建行为。
具体首次发现见 [前次报告](AUDIT_2026-09-04.md)。

这是基于历史变更与风险的源码复核及动态验证，不代表逐行检查了全部源码或 vendored 引擎，
也不代表独立第三方审计。

## 本次新增修复

| 编号 | 严重度 | 触发条件与影响 | 修复和证据 |
| --- | --- | --- | --- |
| S01 | 高 | 回放把本批脚本任务推迟到下一批检查，但本批已交给 chainstate；直接后端、写回限额或维护刷新均可能持久化无效区块。 | 每批所有脚本完成且通过后才提交，保留批内并行。`replay_script_carry_cannot_commit_an_invalid_batch` 在修复前实际失败；修复后确认错误事务索引、tip 未推进、原输入未花费，且无遗留脚本任务。 |
| S02 | 高 | 预取在上一批提交前读取；提交已经持久化并从写回层回收后，仅覆盖仍在缓存中的键会漏掉已完成提交的变化，导致过期 coin 被使用。直接数据库的默认协调实现也不刷新。 | `ExecutionChainStore::reconcile_prefetch` 从当前逻辑视图重新读取，并检查数量及键顺序，错误向上传播。回归测试同时验证写回包装与直接 redb：旧 coin 消失，新 coin 可见。 |
| S03 | 高 | pending 移交后台线程、后台任务回收期间有可见性空隙；读者可能看到旧 durable 状态，或组合不同代的缓存。并发启动也可能覆盖尚在执行的任务。 | pending 锁覆盖前一任务结算与下一任务发布；读者先固定 pending，再取得 in-flight，直到底层读取结束。失败标记在取得修改锁后复查，保证失败后不再接受修改。已有并发提交与回收测试通过。 |
| S04 | 高 | 创建写回线程失败时，已取走的 pending 随局部变量丢弃，tip 与 UTXO 丢失。 | 失败后恢复整批 transitions、coin、spend、tip 和计数。注入线程创建失败，验证缓存可读、durable 未变，且重新 flush 成功。 |
| S05 | 中 | 默认功能构建引用只在 MDBX 下使用的符号；部分 MDBX 诊断示例与测试未声明所需功能；fuzz 使用 Rust 1.85 尚未稳定的语法/API。 | 修正功能门控及 Cargo `required-features`；将 let-chain / `as_chunks` 改为兼容写法，补位运算括号。默认功能、全部功能、fuzz 严格 Clippy 均通过。 |
| S06 | 低 | ZMQ 关闭测试仅接受 EOF；关闭仍有未读订阅数据的 TCP socket 可以返回 ConnectionReset，造成误报。 | 接受 EOF 或 ConnectionReset，仍要求超时内关闭且运行时任务恢复基线。完整测试中验证。 |

S01 取消跨批脚本验证与提交重叠；S02 为保证一致性会重新读取预取键。
这些选择可能降低回放吞吐量；本次没有重新进行主网全量性能基准，不能沿用旧基准数值声称性能不变。
`reconcile_prefetch` 现在返回 `Result`，调用方必须处理读取失败。

## 依赖更新

核实主项目全部直接及开发依赖，同时更新两个独立 Rust 工作区的锁文件和 Go 基准模块。
相对于合并的远端基线，主锁文件更新 19 个包版本；fuzz 锁文件更新 30 个包版本，
并补入默认 allocator 所需的 mimalloc 两个包。直接依赖最低版本提升到本次核实的稳定版，
例如 chacha20 0.10.2、serde 1.0.229、thiserror 2.0.20、tokio 1.53.1。
zstd 从 0.13.3 升级到 0.14.0，zstd-safe 从 7.2.4 升级到 8.0.0。
两个工作区保留 Rust 1.85 最低版本，目标专用 wasip2 保留兼容版本；
fuzz 明确声明 MSRV，并与主项目保持 libmdbx 路径补丁一致。

Go 存储基准将 Pebble v1.1.5 迁移到 `pebble/v2` v2.1.7，适配默认配置、压缩、日志与带 context 的压缩 API，
保持无压缩与 Bloom-10 的基准配置，同时更新输出中的引擎版本。
更新实际依赖图中的压缩、遥测、protobuf、Prometheus、缓存及系统库，重新执行 `go mod tidy`。
Badger v4.9.6、bbolt v1.5.0、现有 goleveldb 版本已核实并保留。
更新后的 Go 库要求至少 Go 1.26；初次 govulncheck 在本机 Go 1.26.0 上报告 13 项可达标准库漏洞。
最低版本进一步提升到官方维护版本 Go 1.26.8，复扫结果为 `No vulnerabilities found`。

明确保留的 Rust 版本：

- **redb 2.6.3**：最新主要版本为 4.2.0，要求 Rust 1.90，并涉及旧数据库格式支持与本仓库补丁移植。
  vendored 2.6.3 的变更记录明确说明 3.x 仅支持 v3 格式；直接替换会影响现有数据库。
  本次保持格式兼容，未声称已经完成 redb 4 迁移。
- **rusqlite 0.31.0**：最新独立版本为 0.40.2，但当前最新 BDK wallet 3.1.0 经 bdk_chain 0.23.3 依赖 rusqlite 0.31.0。
  单独提升基准依赖会造成 `libsqlite3-sys` 原生链接版本冲突，需等待或协同迁移 BDK。
- **bitcoinconsensus / libmdbx 本地补丁**：保留现有上游版本及已审计的补丁，没有用注册表副本覆盖补丁。

版本核实来源：[crates.io 官方接口](https://crates.io/api/v1/crates/redb)、
[BDK 发布源码](https://docs.rs/crate/bdk_chain/0.23.3/source/Cargo.toml)、
[Go 官方发布列表](https://go.dev/dl/?mode=json)、Go 模块代理及校验数据库。
数据库兼容约束也可在 [vendored redb 变更记录](../vendor/redb/CHANGELOG.md) 中核对。

CI 新增默认功能与 fuzz 的 Rust 1.85 严格 Clippy 检查，以及固定 govulncheck v1.7.0 的 Go 扫描。
既有所有功能检查、漏洞策略和覆盖率门槛保留。
